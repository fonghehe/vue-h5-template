# FAQ

## Installation and module resolution

Use Node 22.18+ within 22.x or 24.x and pnpm 11.10.0. Run `pnpm install` after workspace dependency changes. If a running server reports `Failed to resolve import @vh5/mobile-ui/...`, stop that old server, restart `pnpm dev:vant` and reload the browser. Rebuilding or passing tests in another port does not repair an old process.

## Ports and Mock

Vant fails on an occupied 5778 port; choose another explicitly with `VITE_PORT=5788 pnpm dev:vant`. Verify what already runs on 5320 if Mock is unavailable: the plugin does not replace an existing process. In service mode confirm business 8002 and AI 8001 are running; do not use Nitro credentials by assumption.

## White Vant header

Use `@vh5/styles/vant`; navigation variables must be on `.van-nav-bar`, not only `:root`. Late Vant defaults otherwise reset the header. See [styles](../essentials/styles.md).

## Types and changes

Run `pnpm typecheck`, not the obsolete `pnpm check:type`. Shared UI/API/AI/Vite config have their own type-check scripts. Vant checks application code and `tsconfig.node.json`. Auto-import declarations are generated by Vite; route records remain handwritten.

## Adding features / deploying

Use [the feature guide](../essentials/contributing-features.md), [backend modes](../essentials/server.md) and [build instructions](../essentials/build.md). Subpath/PWA and the legacy playground Dockerfile need deployment-specific review. Do not delete lockfiles as the first response to install failures.
